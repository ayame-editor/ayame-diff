# ADR 0006: シンタックスハイライト — 現状は複数行対応の近似、tree-sitter は保留

- ステータス: Accepted（2026-09-27）
- 関連 Issue: hjosugi/ayame-diff#287
- 参考: ADR 0002（ゼロ依存方針）、ADR 0003（依存性の例外）

## 背景

Issue #287 は、クライアント側のシンタックスハイライタ
（`internal/server/web/syntax.js`）を tree-sitter に置き換えることを提案して
いる。複数行にまたがる構文（ブロックコメント、複数行文字列、テンプレート
リテラル、ヒアドキュメント）を正確に色付けし、将来の構文を理解した構造的
差分への足がかりにするためである。

現在のハイライタは意図的に**行ローカル**であり、パーサ状態を保持せず、
ファイル全体も走査しない。そのためブロックコメントや複数行文字列の2行目を
色付けできず、#152 では自前トークナイザの保守コストも見えている。

## 決定

**tree-sitter および WASM 文法はまだ同梱しない。** 標準ライブラリのみの
ビルド、ネットワークを使わないオフラインGUI、小さな埋め込みアセットの枠を
維持し、その代わりに既存のハイライタを限定的に高精度化する:

- `syntax.js` に小さな状態機械（`createHighlighter`）を追加し、対象とする
  複数行構文について連続する行をまたいで状態を保持する。
- 変更しない行ローカルの `highlightSpans` が**劣化パス**であり続ける。正確な
  色付けが使えない場合（未知の拡張子、データ/マークアップ/ログ形式、古い
  フロントエンド、エラー時）や、状態を信用できない場合（ハンク間で省略され
  た行、順不同で取得したコンテキスト）は、この行ローカル方式へそのまま
  フォールバックする。
- 精度の限界は隠さず文書化する。

## まだ tree-sitter を採用しない理由

- **バンドルサイズ。** SPA は Go バイナリに埋め込まれる（`//go:embed web`、
  `docs/gui.md` 参照）。`web-tree-sitter` と言語ごとの文法 `.wasm` は数百KB
  から数MBになる。バンドラもビルド手順もなく（素の `<script>` ファイル）、
  ランタイムと文法を明示的に同梱・読み込みする必要があり、その増加を全
  ユーザーが負担する。
- **オフライン/ネットワーク非依存。** 提案では文法を遅延読み込みするため、
  バイナリに同梱しない文法は実行時に取得することになり、オフラインGUIの方針
  と矛盾する。全文法を同梱するのは逆のトレードオフである。
- **コストの前に証明を。** 完了条件（複数行構文の正確な色付け、失敗時に
  無言で壊れない、許容範囲のバンドル増加）は、状態機械がほぼアセットコスト
  ゼロで一般的な構文について満たす。
- **difftastic の教訓。** 作者自身が、構造的差分は変更の多いファイルで
  スケールが悪くメモリを大量に使うと述べている。まず可視の劣化トリガ
  （未知の拡張子、パースエラー、サイズ/計算量超過）を持つべきであり、行
  ローカルのフォールバックはそれを既に提供している。
- **保守。** 文法ごとにバージョンとライセンスが付いて回り、更新対象が増える。
  現在はそれを自動化するツールチェーンがない。

## 実装

- `internal/server/web/syntax.js`: `createHighlighter(path)`（`reset`/`state`
  付きの状態機械）、`highlightLines(lines, path)`、`sliceSpans(spans, …)`。
  `highlightSpans` と `languageForPath` は変更しない。
- 対象構文: `/* … */` ブロックコメント、JavaScript/TypeScript のテンプレート
  リテラル、Go の raw 文字列、Python の三連引用符文字列、シェルの
  ヒアドキュメント（`<<`、`<<-`、引用符付き区切り）。
- `internal/server/web/app.js`: 描画前に各ハンクの行を左右それぞれの順で
  色付けし、省略された行のギャップで状態を破棄する。正確なスパンは
  ルックアップとして使われ、見つからない場合は `highlightSpans` に落ちる。

## 既知の限界（未実装）

- 入れ子の区切り（Rust の入れ子ブロックコメントは最初のマーカーで閉じる）。
- テンプレートリテラル内の `${…}` 補間は文字列として色付けされる。
- 1行に複数のヒアドキュメント、here-string（`<<<`）。数値のシフトは除外するが、
  `$(( ))` 演算内で識別子が続く `<<` はヒアドキュメント開始と読まれうる。
- YAML のブロックスカラー、Rust の raw 文字列など言語固有の形式。
- 構文を理解した構造的差分（関数名を出すハンクヘッダ、構文ブロック単位の
  折りたたみ、空白のみの再インデント）は、#287 自身が切り出しているとおり
  別の将来 Issue とする。

## 再検討の条件

オフラインで、ツールチェーン不要で同梱できる tree-sitter ランタイムと小さな
文法セットが、埋め込みアセットとライセンスの枠に収まり、かつ複数行の色付けが
実用上明らかに不足したとき。採用する場合も、未知の言語・パース失敗・
サイズ/計算量超過のすべてが変更なしの行ローカル方式に落ちる、必須の劣化
トリガを同梱すること。
