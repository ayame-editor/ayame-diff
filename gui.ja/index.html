    GUI¶

    ayame-diffは、小さなローカルウェブアプリをバンドルしており、ターミナルの代わりにブラウザでファイルを比較できます。シングルページアプリはバイナリに埋め込まれているため、追加のインストールや外部ネットワークアクセスは必要ありません。

    初回比較まではパス入力を大きく表示し、比較後は編集可能なスティッキーペインヘッダーへ置き換わります。

    2つのサブコマンドで起動します：

    • serve — 固定のアドレス（デフォルトはlocalhost）でサーバーを起動します。
    • gui — 空いているlocalhostのポートでサーバーを起動し、ブラウザを開きます。

    ローカル・シングルユーザー専用

    サーバーはブラウザで入力したファイルパスを開くため、デフォルトでlocalhostにバインドされており、あくまでご自身のローカル環境での使用を想定しています。ネットワークに公開しないでください。 loopback以外の--addrには--allow-remoteが必要で、警告が表示されます。 URLを持つ人は誰でも操作できるため、信頼できるネットワークのアクセス制御下に置いてください。

    結果内の検索¶

    Ctrl+F で結果に対する検索バーが開きます。一致箇所をハイライトして件数を表示し、 Enter / Shift+Enter で次/前へ移動、Esc で閉じます。トグルで「変更行のみ」に 絞り込み、大小区別、正規表現の扱いを切り替えられます。

    照合は行全体のテキストに対して行うため、アンカー（$）や複数のシンタックストークンに またがるパターンも記述どおりに動作します。行番号の桁は検索対象外なので、数字で検索しても 行番号ではなく内容に一致します。ハイライトする件数には上限があり（非常に大きな差分で 広範な検索をしても描画の分割を損なわないため）、上限に達した場合はカウンタに + が付きます。

    アクセス制御¶

    起動のたびにAPIトークンを生成し、すべての/api呼び出しにX-Ayame-Tokenヘッダーで 必要とします。トークンはguiが開くURL・serveが表示するURLに含まれ、ページは sessionStorageに保持するため、通常のリロードでは動作し続けます。表示されたURLを 開いてください。新しいタブでhttp://127.0.0.1:PORT/だけを開いてもトークンがないため、 UIがその旨を表示します。

    この設計から2つの性質が導かれます。

    • CSRFが成立しない。 他のサイトのページはCORSプリフライトなしにカスタムヘッダーを 付けられず、このサーバーはプリフライトに応答しません。Cookieであれば自動的に送信されて しまい、保護になりませんでした。
    • DNSリバインディングが成立しない。 loopbackで待ち受ける場合はHostヘッダーを バインドしたアドレスに固定します。自分のホスト名を127.0.0.1に解決させたページも Hostにはそのホスト名を送るため、正しいトークンを持っていても拒否されます。

    埋め込みページとそのアセット、/api/healthはトークンなしで開いています。ページは自身の サブリソースにヘッダーを付けられず、起動コマンドはブラウザが存在する前に死活確認として healthを叩くためです。いずれもユーザーのデータを露出しません。

    --allow-remoteのリスナーはHostを固定しません。到達しうる名前をここでは知りえない ためで、その場合はトークンが防御になります。

    serve¶

    ayame-diff serve [--addr host:port] [--allow-remote]

    ウェブUIを起動し、上部バーのサーバーを停止、Ctrl+C、SIGINT、または SIGTERMで停止するまで動作し続けます。停止時は処理中のHTTPリクエストを完了させて からリスナーを閉じます。外部変更の監視のように待機しているだけのリクエストは、 ポーリングの残り時間を待たずに即座に終了するため、停止操作はすぐに完了します。

    ayame-diff serve                       # http://127.0.0.1:8080
ayame-diff serve --addr 127.0.0.1:9000
ayame-diff serve --addr 0.0.0.0:8080 --allow-remote
    フラグ デフォルト 意味
    --addr 127.0.0.1:8080 受信アドレス（host:port）。
    --allow-remote オフ loopback以外の受信アドレスを明示的に許可します。APIトークンは有効ですが、Hostの固定は行いません。

    指定した固定ポートが使用中の場合は競合を報告し、次の空きポートへ自動的に切り替えます。

    gui¶

    ayame-diff gui [--addr host:port] [--allow-remote] [--no-open]

    serveと同じUIですが、空いているlocalhostのポートを選び、デフォルトのブラウザを起動します — ネイティブのWebView依存なしで「ダブルクリックしてGUIへ」体験を提供します。

    ayame-diff gui             # 空いているポートを選び、ブラウザを開く
ayame-diff gui --no-open   # サーバーを起動するが、ブラウザは開かない
    フラグ デフォルト 意味
    --addr 127.0.0.1:0 受信アドレス；ポート0は空いているポートを自動選択します。
    --allow-remote オフ loopback以外の受信アドレスを明示的に許可します。APIトークンは有効ですが、Hostの固定は行いません。
    --no-open オフ サーバーを起動しますが、ブラウザは開きません。

    GUIで固定ポートを明示した場合も同じフォールバックを使います。デフォルトのポート0は OSへ空きポートの選択を任せます。

    guiで開いた各ブラウザタブは、認証済みのリースを1つずつ保持します。最後のタブを 閉じると、再読み込み用の短い猶予時間を置いてサーバーを停止するため、ダブルクリック 起動でも孤児プロセスを残しません。終了通知を送れずにタブやブラウザが異常終了した 場合も90秒後にリースが失効します。--no-openでは、表示されたURLを90秒以内に 開いてください。明示的なサーバーを停止ボタンはguiとserveの両方で使えます。

    ウェブUIの使い方¶

    LEFTとRIGHTのファイルパス（またはサーバー側のファイルピッカーを使用）を入力し、モード（text、sorted、またはcsv / tsv）とオプション（エンコーディング、再同期ウィンドウ、ケース無視、空白文字処理、EOL制御、再インデントを吸収、行ごとに入力する正規表現フィルター、sortedの場合は数値/逆順ソート）を選択して、比較をクリックします。結果は、行番号や単語レベルのハイライト付きのサイドバイサイドグリッドとして表示されます。パッチ形式（normal、context、unified）とコンテキスト行数を選び、パッチのエクスポートを使って適用可能なayame.patchをダウンロードします。パッチのエクスポートはCRLFや最後の改行マーカーを保持し、バイナリやNUL入力は拒否します。エクスポートはtextモードのみ対応；sortedビューのパッチは安全に元のファイルに適用できません。どの結果も上部に統計パネルが開き、行より先に変化の全体像を示します。text / sortedの結果では、変更行数とファイル全体に占める割合、最大ハンクを種別ごとの合計とともに表示します。CSV を書き出すは長形式の表（section,column,metric,value）を、JSON を書き出すは同じ集計をJSONでダウンロードします。どちらもブラウザ内の集計から生成するため、書き出しで再比較は発生しません。

    結果をどう読むかは、何を比べたかとは別です。 結果ツールバーに読み方（text／sorted／csv / tsv）があり、切り替えると同じ入力のまま新しい読み方で再比較するため、読み方を間違えても入力し直さずに試して戻せます。読み方が意味を持つときだけ表示されます。フォルダ比較に読み方はなく、3ファイル比較はテキストかCSVとして読めますがソート済みにはできません。sortedの数値／逆順ソートやCSVの設定は、その読み方に必要なときに現れます。

    同じ出力メニューには確認レポートを書き出すがあります。これは確認作業の記録を書き出します：比較対象（サイズ、更新日時、検出エンコーディング、SHA-256ハッシュ）、適用した比較条件（無視設定、行フィルタ、同期点、ウィンドウ、移動検出）、差分の総数、無視した各ハンクとその理由、既読/未読の確認状態、そして比較を再実行するためのバージョン付きURL状態です。印刷可能な自己完結HTML、Markdown、またはJSONを選べます。比較した内容は既定では含まれません。レポートをファイルの中身ごと共有してよい場合にだけ差分の内容を含めるをオンにしてください。確認済みハンクの追跡は#288で追加されるため、このビルドのレポートには確認済みハンクが記録されていないことが明記されます。

    シンタックスハイライトは、一般的なソース、データ、マークアップ、ログ形式に色付けを行います。言語はファイル拡張子で選ばれ、オン/オフはブラウザに記憶されます。複数行にまたがる構文を扱う言語（ブロックコメント、JavaScript/TypeScriptのテンプレートリテラル、Goのraw文字列、Pythonの三連引用符文字列、シェルのヒアドキュメント）では、表示中の連続した行をまたいで状態を保持するため、その構文の終端まで色付けされます。走査するのは描画済みの差分行だけで、入力ファイル全体は走査も保持もしません。そのため、ハンクの先頭より前で始まる構文や、ハンク間で省略された行をまたぐ構文は追跡されず、従来の行ローカルの色付けのままになります。正確な色付けを利用できない場合（未知の拡張子、データ/マークアップ/ログ形式、古いフロントエンド、エラー時）は、従来の行ローカルなハイライトへそのままフォールバックします。tree-sitter文法をまだ同梱していない理由はADR 0006を参照してください。

    結果が表示されると、初回用のパス入力レールは作業領域から消えます。各スティッキー ペインヘッダーには、側の識別子、編集可能なパス、サーバー側ファイル参照ボタン、 取得できる場合は検出文字コードと行数が表示されます。編集後にEnterを押すか フォーカスを外すと、その片側を差し替えて即座に再比較します。⇄でLEFT/RIGHTを 入れ替えられます。再比較後は先頭へ戻らず、直前に見ていた論理行を復元します。

    比較条件と既定¶

    比較条件（大小無視、空白、改行コードの扱い、行フィルタ、移動検出）は保存された 既定から始まります。1つ変更しても、その比較にだけ効く値になり、この設定を既定に するを押すまで保存済みの既定は書き換わりません。見出し横のチップが現在有効な範囲 （既定を使用中、または今回のみ・既定とN件違い）を示し、グループのバッジが既定と 異なる条件の件数を数えるため、一時的な変更が次回の既定になってしまわないことが画面 から分かります。既定に戻すで保存済みの値に戻せます。比較URLや.ayamediff プロジェクトを開いた場合も、その条件は今回の上書きとして適用されるため、共有された リンクを開いても自分の既定は書き換わりません。この規則が効くのは比較条件グループだけ で、エンジン調整やモード固有のオプションは既定には保存されません。

    ペインの編集¶

    結果ツールバーの編集で、左右どちらのファイルも直接編集できます。表示されるのは 実ファイル2つのtext比較のときだけです。貼り付けたテキストには保存先がなく、 sorted・csv / tsv・フォルダ・3-way は行の並びや形を変えるため、画面上の行が ファイルの行を指さなくなるからです。

    有効にすると両方のファイルを全文（各8MiBまで）読み込み、ディスクの内容ではなく ペインの内容を比較します。行をクリックするか、フォーカスしてEnterで編集を開始し、 Enterで確定、Escapeで元に戻し、他へ移動しても確定します。再比較は1文字ごとでは なく行の確定時に走り、IMEの変換中は再比較しないため、日本語入力が途中で妨げられる ことはありません。

    確定した行はその場で表示されます。編集したセルはバッファの内容で描画され、暫定で あることを示すバーとともに表示され、本計算の結果で置き換わります。本計算が届くと 結果全体を差し替え、直前に見ていた論理行を復元するため、画面は跳ねません。連続した 確定はまとめられ、計算中の編集は確定ごとに1回ではなく、まとめて1回の追いつき計算と して実行されます。新しい計算を始めると前のリクエストはキャンセルされます。暫定の 判定で同じ／変更を付け直すのは、素の厳密なテキスト比較のときだけです。大文字小文字 を無視、空白ルール、改行コードを無視、行フィルタ、移動検出、同期ポイントがある 場合や、対応する行が画面に無い場合は、入力したテキストだけを表示し、判定は本計算に 委ねます。比較条件の変更はローカルに正直な近似ができないため、結果が届くまで従来の 進捗表示のままです。またこのペインが編集するのは行の内容だけで、行の挿入・削除は 行いません。

    各ペインヘッダーには、未保存の変更を示すマーカー、その側だけを保存する保存 ボタン、書き込みできない場合の読み取り専用バッジが表示されます。Ctrl+Sでも 編集中のペインを保存できます。保存では元ファイルの文字コード・BOM・改行コード・ 末尾改行の有無を保持するため、1行直しただけでファイル全体が別物に変換されることは ありません。開いたあとにディスク上でファイルが変更されていた場合、保存は中断され、 上書きするかどうかを確認します。未保存のまま離脱しようとすると警告し、外部変更の 自動反映も未保存の編集を上書きせず、確認バーを表示します。

    編集中は2種類の差分が同時に画面へ出ますが、見た目は区別されたままです。比較した 2ファイルの違いはセルの背景色と、1列表示での-/+マーカーです。バッファが読み込んだ ファイルと文字が異なる行——このセッションで入力した行——には、ガターに専用のハンドル （~のグリフ付きアクセントバー）が付き、背景色とは別の表現になります。ハンドルを クリックすると、その連続した行をまるごと読み込み時の内容へ戻せます。行にフォーカスして Deleteでも同じです。保存するとハンドルは消え、編集を破棄したときも消えるため、 指していた変更より長く残る印はありません。

    編集対象を差し替える操作（別のパス、モードの切り替え、 テキスト貼り付けの有効化）は必ず確認し、取り消せばその場に留まります。再比較や 比較条件・表示設定の変更はバッファを保持するため確認しません。

    編集できるのは行の内容です。行の追加・削除は対象外で、比較設定は読むときと同様に 適用され続けます。

    表示幅と CJK の桁揃え¶

    列が揃うのは、1行のラテン文字と CJK を単一のフォントが描画する場合だけです。 CSS は文字単位でフォントを選ぶため、CJK を持たないラテン専用等幅フォントを CJK 対応フォントより先に置くと、name 名前 のような行は送り幅の比が正確に 1:2 でない2つのフォントで描かれ、桁がずれます。そのためファミリの並びは ラテンと CJK の両方を収録する Noto Sans Mono CJK JP、Source Han Mono JP、 Windows 同梱の MS Gothic を先頭側に置き、ラテン専用フォントはその後ろに なります。これらのどれも入っていない環境では混在行を揃えられないため、 Noto Sans Mono CJK JP を導入すると揃います。

    これを調整する表示設定が2つあり、CLI と同じ意味を持ちます。

    • タブ幅（2、4、8、既定 8）は CSS の tab-size トークンとして 適用されます。CLI はタブを展開しません。internal/textwidth はタブを0セルと 数え、端末は独自のタブストップで展開するため、一致させる単一の CLI タブ幅は 存在しません。GUI は幅を明示し、一般的な端末値である8を既定にします。
    • ○ ※ α を全角扱い（East Asian Ambiguous 文字）は internal/textwidth の Options.EastAsianAmbiguousWide と CLI の --east-asian-ambiguous-wide に対応します。既定はオフで、これらを1セルで 描く端末に一致します。フォントが全角で描く場合はオンにします。

    テストされるのは両者が共有する幅・整列の判断であり、ピクセル結果ではありません。 GUI の textwidth.js は同じ入力について CLI の internal/diffout 出力と internal/textwidth に突き合わせて検証しますが、ブラウザが実際に描く字形の 送り幅はインストールされたフォントに依存します。

    進捗とメッセージ¶

    実行中の比較は専用の進捗行に表示され、操作の結果（マージの保存、パッチの書き出し、 比較の失敗など）はその下のメッセージレーンに積み上がります。メッセージは互いを 上書きしないため、次の試行を始めた後でも前回の結果を読み返せます。成功は数秒で 自動的に消え、警告と失敗は閉じるボタンかフォーカス中のEscapeで閉じるまで残ります。 同じメッセージが繰り返された場合は行を増やさず回数を数え、各行には到着時刻を 表示します。

    テキスト比較の進捗行は、実行時間だけでなく今どの段階にいるかを示します。入力の 読み込み、比較、移動ブロックの検出、結果の送信、描画の各段階と、その段階で経過した 時間です。実際の件数がある段階（結果ページの受信、描画済みハンク）はその割合を表示し、 件数の無い段階は不定表示のままにします。偽の割合は出しません。結果は上限付きの ページに分けて送られるため、全件が届く前に先頭のハンクを読み始められます。変更の ない文脈はハンクの位置が確定してから挿入されます。maxHunks がハンクを切り捨てた 場合や maxLines が長いハンクの行を省略した場合は、切り詰められた結果を読む前に メッセージレーンで警告するので、その場で上限を上げられます。Cancel は実行中の リクエストを即座に中断します。

    大きな結果は一括ではなく分割して描画されるため、描画中もスクロールと入力が 効きます。キャンセル は実行中のリクエストだけでなく、すでに始まっている 描画も停止します。

    アクセシビリティとキーボード操作¶

    差分の判別は色の知覚に依存しません。左右表示・1列表示のどちらでも、追加行は ガターに+、削除行は-を持ち、各ハンクの見出しは種類を文字で示します （+ Insert、− Delete、~ Replace、MOVED #…）。3-wayの競合には≠が付きます。 強制配色モードで背景の色がすべてシステム色に置き換わっても、この記号は残ります。 どの行が何なのかを示すのは背景色ではなく記号です。

    支援技術には同じ情報を言葉で渡します。各差分行は行番号とともに追加・削除・ 変更として名付けられ、各ハンクはラベル付きのグループになります。ナビゲーション のフィードバック（Alt+↓後の位置、検索のステップ、マージの選択）は1つの politeライブリージョンだけに集約し、失敗はメッセージレーンのassertiveで通知 します。表示中のカウンタ（差分の位置、検索ヒット数、未解決数）はライブリージョン ではなく、それを変えるコントロールがカウンタを説明として持つため、1回のキー操作で 複数の読み上げが重なることはありません。

    主要な流れはキーボードだけで完結します。Tab/Shift+Tabで全コントロールに到達し、 Alt+↓/Alt+↑（Alt+Home/Alt+End）で差分間を移動、Alt+←/Alt+→ （3-wayではAlt+B）で採用する側を選択、Ctrl+Fで検索、Ctrl+Sで編集中のペインを 保存、Escapeで検索と各ダイアログを閉じます。フォーカスリングは差分行やミニマップ を含むすべてのコントロールで表示されます。

    制限も2つあります。画面外のハンクは、巨大な差分で文書全体を一度にレイアウトしない ようCSSのcontent-visibility: autoを使っています。一部のブラウザはこの画面外 コンテンツをアクセシビリティツリーからも除外するため、スクロールして一度も表示 していない差分にはスクリーンリーダーが到達できないことがあります。読む前に差分 ナビゲーションでそのハンクを画面へ出してください。移動に伴い位置は読み上げられます。 ミニマップはテキスト文書ではなく概要です。スクロールバーとしてキーボード操作は できますが、マーカー自体にテキストはありません。

    これらの記号、ライブリージョンの構成、フォーカスリングの網羅はCIで実行される自動 テストで固定しています。Goのテストが配信されるアセットを読み、node --testの スイートが純粋なマッピングを実行します。axeやLighthouseの完全な実行にはヘッドレス ブラウザとNode依存が必要で、このプロジェクトはそれを持たないため、 GUI退行防止チェックリストの手動確認として残します。

    外部変更¶

    ファイルを使うtext、sorted、csv / tsv、3-way比較では、表示メニューの 外部変更を自動反映がデフォルトで有効です。別のエディタで比較対象を保存すると、 短時間の複数writeやアトミック保存を1回にまとめて再比較し、同じ論理行を同じ画面内 位置へ復元します。

    ブラウザは認証済みfetchの長期ポーリングを使うため、監視リクエストにも他の ファイルシステムAPIと同じX-Ayame-Tokenが付きます。監視対象はBASE/LEFT/RIGHTの 最大3パスで、ページ・パス・モード・設定が変わると未完了リクエストを中止します。 将来の直接編集で未保存変更がある場合は勝手に置き換えず、再読み込みまたは 現在の編集を保持を選ぶバーを表示します。

    貼り付けテキストには監視するファイルがありません。フォルダ比較も手動のままです。 任意サイズのツリーを保存のたびに再帰走査すると、リソース上限を保証できないためです。 フォルダ結果から変更ファイルをテキスト比較として開いた後は、そのファイルペアを通常どおり 監視します。

    テーマと配色¶

    表示メニューではテーマ（システム・ライト・ダーク）と配色（デフォルト・色覚配慮・ カスタム）を選べます。配色をカスタマイズ…は、結果全体を駆動するデザイントークンの 編集画面を開きます。背景と文字の色、アクセントと状態色、追加・削除・変更の淡い塗りと 単語ハイライト、フォントファミリと文字サイズのトークンが対象です。編集はその場で ページへ反映されるため、別画面のサンプルではなく、画面に出ている比較そのものが プレビューになります。

    テーマはベース（システム・ライト・ダーク）と名前を持つ、トークン上書きのJSONオブジェクト です。保存はその名前でブラウザに保存し、編集画面の一覧へ追加します。JSONをコピーと JSONを読み込むはテーマをマシン間で移動できるため、チームで配色を標準化できます。 プリセットに戻すは同梱のプリセット（Ayame Light/Dark、WinMerge、VS Code Dark+、 Solarized Light、ハイコントラスト）へ戻します。

    トークン編集の下には、その配色が意味する前景/背景の各ペア（背景上の本文、アクセント ボタンのラベル、各差分の前景と淡い塗り）のWCAGコントラスト比が表示され、AA基準を 下回るペアには印が付きます。カスタム配色で#150の「同色に紛れて読めない」状態を 警告なしに再現することはできません。

    テーマと配色の選択はブラウザ全体の設定で、すべてのタブで共有されます。

    比較URLとブラウザ履歴¶

    ファイルを使う比較が成功すると、GUIは入力パス、モード、比較条件をバージョン付きの URLフラグメントへ保存します。再読み込み時は同じ状態を復元して自動比較します。 異なる入力の比較は履歴を追加し、条件変更は現在の履歴を置き換えるため、戻る・進むで 比較状態ごと移動できます。

    フラグメントはサーバーへ送信されませんが、ローカルパスを含みます。結果ツールバーの リンクをコピーはこの点を警告し、APIトークンを除いたURLをコピーします。 コピーしたURLだけではアクセス権を付与しません。受け取った側では、先にayame-diffを 通常どおり開き、そのブラウザセッション自身のトークンを用意してください。

    貼り付けたスクラッチテキストは意図的に対象外です。URL状態の上限は32 KiBです。 非常に多いCSV列選択は.ayamediffプロジェクトへ保存してください。

    折り返し・ワードハイライト・シンタックスハイライト・空白表示・テーマ・配色・表示形式 といった表示設定は一度だけ保存され、すべての比較に適用されます。比較条件はモードと 入力パスの組み合わせごとに保存されるため、同じ比較を開き直すとそのときに使った条件が 復元され、別の組み合わせは既定値から始まります。

    複数比較のタブ¶

    複数の比較を同時に開いたままにできます。最初の比較が成功するとパスの上に タブバーが現れます。＋ は現在の比較から新しいタブを開き（片側を変えて 再比較します）、タブの × は閉じます。アクティブなタブは強調表示され、 アクティブなタブを閉じると隣のタブがアクティブになります。

    タブごとに入力、モード、比較条件、スクロール位置を保持します。タブを 切り替えるとその状態を再適用して結果を再計算します（すべての差分をメモリに 保持しないため）。スクロール位置と編集内容は保たれますが、大きな比較は開く たびに再計算されます。タブ集合はアクティブな比較と同じURLフラグメントへ 保存されるため、再読み込みで開いていたタブが復元されます。履歴エントリごとに タブ集合を持つので、戻るではその比較に対応するタブへ戻ります。 リンクをコピーは1つの比較だけをコピーし、他のタブは含めません。

    適用された無視設定は結果のサマリーと条件ツールバーに表示されます。これらはマッチングにのみ影響し、レンダリングされた行やエクスポートされたパッチは元のテキストを保持します。空白のみ・大小のみの差分は消去されません。格下げされた市松模様のハンクとして表示され、専用の無視のみカウントを持ちます（KDiff3の第三の状態）。次/前のナビゲーション、差分件数、パッチエクスポートでは等しいものとして扱われます。したがって、無視した差分は「存在しなかった差分」と区別でき、後から確認できます。

    再インデントを吸収は、どの行が対応するかとどの対応を差分として数えるかを分離します（#270）。チェックすると空白を無視するのは位置合わせのためだけになり、再インデントや再整形されたファイルでも全行の対応を保ったまま、内容の差分が元の位置に表示されます。空白のみの行が消えることはありません。whitespace設定が何を差分とするかは変わらず、その設定がすでに空白を無視している場合は何もしません。サーバー側のフィールドはalignWhitespaceです。

    ブラウザからドロップしたファイルは、非公開のローカルキャッシュへコピーされます。 上限は1ファイル2 GiB、1ブラウザセッション8 GiBです。超過時は明確なHTTP 413 エラーを返し、途中まで作成した一時ファイルを削除します。孤立したセッションキャッシュは 24時間後、後続セッションの開始時にクリーンアップ対象になります。

    差分のナビゲーション¶

    スティッキーなナビゲーションバーは最初、前、次、最後のハンクにジャンプし、現在/合計、未読数を表示します。キーボードショートカットはAlt+Down、Alt+Up、Alt+End、Alt+Homeです；?ボタンでUI内のこのリストを表示します。右側のロケーションバーはハンクのインデックスからマーカーを直接描画し、クリックでジャンプ可能、現在のビューポートを重ねて表示します。左右のテキストは縦横ともに同期されており、各ハンクは共有グリッドとスクロール行としてレンダリングされるため、2つの独立したペインではありません。

    マージでは「差分の移動」と「コンフリクトの移動」は別の作業なので、別のキーに割り当てています。Alt+Down / Alt+Up はすべての差分を、Alt+Home / Alt+End は先頭/末尾へ移動し、F8 / Shift+F8 は 3-way 結果のコンフリクトだけを辿ります。Alt+Left、Alt+Right、Alt+B は現在のコンフリクトで左・右・ベースを採用し、Alt+A は両方（左の行の後に右の行）を採用します。マージパネルが開いているときは Ctrl+Shift+S でマージ結果を保存でき、Ctrl+Enter はこれまでどおり比較を実行します。マージパネルの採用後に次へ自動移動を有効にするか Alt+Shift+A を押すと、採用のたびに次の未解決コンフリクトへ進むため、マウスを使わずにマージを完了できます。? ボタンでこの既定マップを一覧できます。

    スクロールによる自動既読とは別に、各ハンクに明示的な確認トグルがあります。通り過ぎただけのハンクは自動で既読になりますが、確認はユーザーの明示的な操作であり、確認済み N / Mカウンタはこちらを数えます。↑✓ / ↓✓ボタンは、まだ確認していないハンクだけを辿ります；最初/前/次/最後は引き続きすべての差分を移動します。確認済みのハンクは表示されたままでエクスポートにも含まれます（「無視」とは異なります）が、内容は薄く表示され、ミニマップのマーカーには枠が付きます。確認状態はlocalStorageへ、比較のパスと各ハンクの種別・範囲・変更行のシグネチャをキーとして保存されるため、同じ比較を開き直すと復元され、比較内容が変わったハンクの確認は外れます。

    ショートカットは固定文字列ではなくデータです。全アクションは1つの表で定義され、?のヘルプ一覧はそこから自動生成されるため、実際に動作しないキーが一覧に残ることはありません。このダイアログのショートカットを変更から、アクションを別のキーへ割り当て直し、defaultとminimalのプリセットを切り替え、プリセットへ戻し、バインド全体をJSONとして書き出せます。2つのアクションが同じキーを主張する場合は両方の名前を表示して警告し、ブラウザが予約しているキー（Ctrl+Wなど）は割り当てを拒否します。選択内容はlocalStorageに保存されるため、個別の比較ではなくブラウザ全体に適用されます。

    動き検出を有効にすると、正確な削除/挿入ブロックをペアリングします。移動したハンクは紫色の専用色で表示され、そのハンクの操作ツールバーの↔ボタンでペアの位置にジャンプします。検出はデフォルトでオフ；最小移動行数とエンジンの候補キャップにより、大規模比較の後処理が過剰にならないよう制御します。

    文脈を有効にすると、各ハンク境界に未変更行を表示します。初期行数は 設定 → 結果表示で指定し（デフォルト3）、0なら展開境界だけを残します。 上／下ボタンは片側から20行、折りたたみ行数のラベルは両端から展開し、ラベルを 展開したい方向へドラッグすることもできます。折りたたみラベルは行数だけでなく 何を隠したかを示します：隠れた行範囲に加え、先頭の隠れ行の抜粋、ソースと 判定できるファイルではシンボル／見出しを表示します。文脈を無効にすると 再比較せずハンクだけの表示へ戻ります。文脈は必要な範囲だけ取得するため、1境界の 展開で巨大ファイル全体をブラウザへ送りません；ラベル用の1行プレビューも同じ 上限付きの方法で取得し、結果へ展開表示はしません。左右表示で編集中は、 両側の文脈行も直接編集できます。

    結果を読みながら比較条件を操作する¶

    差分と見なす基準を変える設定は結果のツールバーに常設され、それぞれ現在値を表示します。これにより、画面の結果がどのポリシーで作られたかをダイアログを開かずに読めます: 空白（量を無視、すべて無視）、大小、改行（改行コード無視、末尾改行無視、両方）、行フィルタ（有効な件数つき）、移動ブロック検出。ツールバーは状態表示も兼ねます。行を変更すると比較設定の対応するコントロールへ書き込み、比較をやり直します。入力は変わらないため、新しい履歴を積まず現在の履歴を置き換えます。

    ツールバーに置くのはトグルのみです。計算量を調整する値 — 移動の最小行数、文脈の行数、行フィルタの定義そのもの — は比較設定に残すため、ツールバーの項目数は固定で、入力に応じて増えません。行フィルタの行は有効な件数を示し、クリックするとダイアログの該当箇所を開いて編集できます。

    手動による整列と無視差分¶

    自動再同期が誤った行を選択した場合、両側の行を1つずつクリックし、同期追加を選択します。同期ポイントは差分を独立した区間に分割し、LEFT:RIGHTのリムーバブルなチップとしてリストされ、即座に再計算されます。ポイントは両側とも増加する必要があり、APIとCLIは範囲と順序を検証します。CLIの同等コマンドは--sync 100:120のように1ベースの行番号を使用します。

    各ハンクにはこの差分を無視もあります。無視されたハンクは折りたたまれた破線のヘッダーとして表示され、次/前のナビゲーションや未読数から除外され、復元も可能です。パッチエクスポートはこれらを省略し、X-Ayame-Ignored-Hunksレスポンスヘッダーに無視されたハンクの数を記録します。これにより、非表示の決定も監査可能です。永続的なルールには宣言的な行フィルター（#28）を使用してください。確認レポートを書き出すは、無視した各ハンクを座標と理由manually ignored during review付きで列挙するので、ヘッダーの件数だけが記録ではありません。

    各ハンクには、そのハンクに固定された小さな操作ツールバーがあります。ハンクにポインタを合わせる、キーボードフォーカスをハンク内へ移す、または⋯ハンドルを押すとツールバーが開きます。ハンドルは常に表示されるため、操作はホバーだけに隠されず見つけられます。ホバーのないデバイスではツールバーを常時表示します。この差分を無視／復元、移動したハンクの↔ジャンプ、マージモード中の採用ボタンはこのツールバーに入り、操作が対象の変更の上に置かれます。全体操作の場所は変わりません：同期追加と差分ナビゲーションはナビゲーションバーに、すべて左 / すべて右 / すべてベースと元に戻す／やり直すはマージパネルに残ります。

    CSV / TSV設定とテーブル結果¶

    csv / tsvを選択し、ヘッダーの検査をクリックします。サーバーは最初の論理レコードのみを読み取り、検出されたフォーマット/パーサと整列された列を報告します。検索可能な列リストは、すべての列、選択キー、除外キーのモードと、「すべて選択」「反転」をサポートします。パース設定、区切り文字、互換性、無視、許容範囲、リソース、一時ストレージ、出力設定も同じ画面で調整可能です；設定の確認は実行結果の概要を示します。

    行・列フィルタは、SQLを書かずに比較条件を組み立てます。条件は「列・演算子（=、≠、含む、で始まる/終わる、>、≥、<、≤、数値範囲、空、正規表現）・値」で構成し、AND/ORと入れ子のグループで結合できます。行の条件は一致しない行を比較前に除外し、列の条件は名前が一致する列を無視します（テキスト欄と同じ宣言的な列無視の仕組みです）。一致をプレビューは入力を走査して左右の残存行数と列数を表示します。組み立てたフィルタはプロジェクトファイルに保存され、従来の行ごとの正規表現フィルタはテキスト向けの高度な代替として残ります。

    結果は100論理差分ごとにページ分割されます。変更されたセルだけが修正色で表示され、ヘッダーバッジは列ごとの変更数を示します。変更された列のみは広い未変更列を隠します。結果上部の統計パネルは、変更のあったすべての列について件数と変更行に占める割合を一覧表示します。数値列では右マイナス左の合計・平均・最大と、増加・減少・表記のみ変更の件数も表示します。一覧は打ち切らずスクロールでき、CSVまたはJSONで書き出せます。サーバーはブラウザの応答を5,000論理差分に制限します；実行とエクスポートは完全なTSV（_changed_cols付き）またはJSON Lines形式の結果をローカルに保存します。テキスト表示と違い、CSVテーブルは差分だけを並べ、未変更行の折りたたみは持ちません。そのため折りたたみバーに表示できるものはありませんが、キー列を明示的に選んでいる場合はページャーに現在のページのキー範囲を示し、表示上限で結果が打ち切られたときは概要にも表示した差分がカバーするキー範囲を示します。

    列名が一致しない場合や、片側にしか列が無い場合は、列の手動マッピングで左の列と右の列を1対1で対応付けられます。対応を「無視」にでき、片側だけの列も許容します。適用すると再比較します。初期値はエンジンが使う列名の整列結果で、#116の内容ベース推定はこのビルドには含まれないため、その旨を表示します。保存した対応付けはプロジェクトに残ります。結果テーブルのヘッダーはドラッグで並べ替えられ、表示だけが変わります。

    サマリーは、比較が動作したメモリ予算と、ディスクへ退避（spill）したかどうかも示します。/api/csv/diffの応答はmemoryオブジェクトを含み、解決後のbudget_bytes、サーバーのcap、そしてエンジンがディスクへ退避した場合にかぎりspill_dirを返します。CSVサマリーは例えばメモリ 512.0MiB / 上限 8GiB・一時ディレクトリ /tmp に退避中と描画します。spill中も比較はキャンセルでき、一時ファイルは成功時・失敗時・キャンセル時に削除されます。

    どう合わせるか（提案）¶

    CSV結果の下のどう合わせるかは、サーバーが返した差分を読み、それを解消する オプション変更を提案します。差分を列順（列名で整列）、末尾や連続する空白、 大小文字、許容差で消える数値の丸め、変更が集中する列（無視候補）に切り分けます。 各カードは推定した原因と、そのオプションを1つ適用して再比較した残差件数を示す ため、「空白を無視」は適用前に「残り 0 件」と読めます。適用はオプションを 設定フォームへ書き込み、再比較し、カードを更新します。提案は重ね掛けでき、2つ目は 1つ目を適用した状態で評価されます。適用した正規化は比較の一部なので、 プロジェクト保存でそのまま保存されます。

    詳細はGUI設定の到達可能性と配置方針を参照してください。 高度な設定への経路を維持しながら、エンジンの全オプションを結果画面へ常設しないための 規則も記載しています。

    フォルダ比較¶

    folder モードは、インクルード/エクスクルード glob、隠しファイル方針、並列ワーカー数、 5種類の比較方法、名前付きフィルタファイル/セット、メタデータの論理フィルタ式を 受け付けます。フィルタをプレビューは内容比較前に選択件数とパス例を示します。 フォルダ設定はポータブルな .ayamediff.json プロジェクトへ保存できます。結果は ステータスフィルター付きのインデントされた色分けツリーです。変更されたファイルを クリックするとテキストモードに切り替わり、対応する相対パスを開きます。 シンボリックリンクはスキップされ、.gz ファイルは展開内容で比較されます。 フラット表示は階層をたたみ、絞り込んだファイルをパス順に、親フォルダを 「場所」列に示して一覧します。深い階層に散在する差分もフォルダを開かずに 見つけられます。ステータスフィルターと検索はそのまま効き、ツリーとフラットの 切り替えで選択とスクロール位置は保たれます。

    通し表示に切り替えると、同じ結果を「差分のある全ファイルを1つのスクロールで 読む」形に変えられます。1ファイルずつ開いて戻る往復が不要になります。各ファイルは 相対パス・状態・ハンク数を持つヘッダーで始まり、そのファイルを読んでいる間ヘッダーは 固定表示され、クリックすると折りたたまれます。ステータスフィルターとパス検索は ツリーと同じように効きます。差分の無いファイルは読むものが無いため含まれません。

    各ファイルの差分は表示領域に近づいたときに取得され、十分離れると解放されます。 そのため100ファイル規模でも同時に保持するのは十数件だけで、解放されたファイルは 占めていた高さを保つため、読んでいる最中に画面が飛びません。差分ナビゲーションは ファイルをまたぎます。読んでいるファイルの中ではハンク単位で移動し、端まで来ると 次の差分ファイルへ（未取得なら取得しつつ）移動します。ミニマップはハンクではなく ファイルを示し、クリックでそのファイルへ飛べます。

    HTTP API¶

    GUIは小さなJSON APIを通じた薄いクライアントです。直接呼び出すことも可能です。

    GET /¶

    埋め込み済みのシングルページアプリを提供します。

    GET /api/health¶

    { "status": "ok", "version": "..." }

    POST /api/diff¶

    リクエストボディ：

    {
  "old": "old.txt",
  "new": "new.txt",
  "mode": "text",
  "encoding": "auto",
  "window": 128,
  "maxHunks": 200,
  "maxLines": 200,
  "numeric": false,
  "reverse": false,
  "ignoreCase": false,
  "whitespace": "none",
  "alignWhitespace": "none"
}
    フィールド 型 備考
    old, new 文字列 比較するファイルパス。
    mode 文字列 text（デフォルト）またはsorted。
    encoding 文字列 --encodingと同じ値。
    window 数値 再同期ウィンドウ（0の場合は128のデフォルト）。
    maxHunks 数値 返される最大ハンク数（0以下は200のデフォルト）。
    maxLines 数値 1ハンクあたりの最大行数（0の場合は200のデフォルト）。
    numeric, reverse ブール ソート制御、sortedモード時に使用。
    ignoreCase ブール 比較時にケースを無視。
    whitespace 文字列 none、change、allのいずれか。何を差分とするかを決めます。
    alignWhitespace 文字列 none、change、allのいずれか。行の対応付けにのみ使用します。changeは再インデントを吸収しつつ、差分は表示されたままにします（#270）。
    syncPoints 配列 0ベースの{ "old": N, "new": N }の強制対応点。
    ignoredHunks 配列 パッチ/レポート出力から除外されたハンクのインデックス。

    成功時のレスポンス：

    {
  "old_lines": 120,
  "new_lines": 118,
  "hunks": [
    {
      "kind": "Replace",
      "old_start": 10,
      "old_len": 2,
      "new_start": 10,
      "new_len": 1,
      "old": ["行 a", "行 b"],
      "new": ["行 A"]
    }
  ],
  "hunk_count": 1,
  "omitted_hunks": 0,
  "added": 0,
  "deleted": 1,
  "modified": 1
}

    各ハンクのkindはInsert、Delete、Replaceのいずれかで、old/new配列に影響行が格納されます（maxLinesにより側ごとに制限）。移動検出を要求したもののハンク省略により完全な結果を出せない場合は、move_detection_skipped: trueが追加されます。リクエストの無視オプションで除外された空白のみ・大小のみの差分は"downgraded": trueとして返されます。そのようなハンクはhunk_countと行統計から除外され、downgraded_hunksがその数を示します。エラーはHTTP 4xxステータスとともにJSON本文で返されます。

    { "error": "right: open /data/right.csv: no such file or directory",
  "code": "file_not_found",
  "path": "/data/right.csv",
  "side": "right" }

    errorは英語の診断メッセージで、これまでどおり常に含まれます。codeは安定した 識別子で、ウェブUIはこれを対処方法つきのローカライズされた文へ変換します。 そのため、syscallやstrconv、encoding/jsonが生成した生の文字列が利用者の目に 触れることはありません。pathとsideは、従来ならメッセージを解析しなければ 分からなかった対象の入力を示します。コードは改名せず追加していきます: file_not_found、permission_denied、invalid_path、invalid_request、 overwrite_refused、unsupported_input、timeout、busy、unauthorized、 internal。未知のコードはHTTPステータスどおりに扱ってください。

    リクエスト例¶

    curl -s http://127.0.0.1:8080/api/diff \
  -H 'Content-Type: application/json' \
  -d '{"old":"old.txt","new":"new.txt","mode":"text","ignoreCase":true,"whitespace":"change"}'

    POST /api/diff/context¶

    未変更行の展開に使う、上限付きの入力範囲を読み込みます。/api/diffと同じ パス／インラインテキスト、モード、文字コード、ソートフィールドに加え、rangesを 指定します。

    {
  "old": "old.txt",
  "new": "new.txt",
  "mode": "text",
  "encoding": "auto",
  "ranges": [
    { "id": 1, "old_start": 7, "new_start": 7, "count": 3 }
  ]
}

    レスポンスは各idと開始位置を、old／newの行配列とともに返します。 1範囲は1～200行、1リクエストは最大512範囲・合計20,000行です。どちらかの入力を 越える座標は拒否されます。

    POST /api/patch¶

    /api/diffと同じパス、インラインテキスト、モード、エンコーディング、比較フィールドを受け取り、追加で：

    {
  "old": "old.txt",
  "new": "new.txt",
  "patchFormat": "unified",
  "context": 3
}

    レスポンスはtext/x-diffで、Content-Disposition: attachment付きです。対応可能なフォーマットはnormal、context、unifiedで、contextは非負で省略時は3です。

    POST /api/report¶

    確認レポート（#296）を生成します。/api/diffと同じパス、インラインテキスト、モード、エンコーディング、比較フィールド（ignoredHunksを含む）を受け取り、追加で：

    {
  "old": "old.txt",
  "new": "new.txt",
  "format": "html",
  "includeContent": false,
  "readHunks": [0, 2],
  "confirmedHunks": [0],
  "comparisonState": { "v": 1, "mode": "text", "paths": {}, "controls": {} },
  "reproduceURL": "http://127.0.0.1:9000/#compare=..."
}
    フィールド 型 備考
    format string json（既定）、markdown、html。
    includeContent bool ハンクの行を埋め込みます。既定はfalseで、これを設定しない限りサーバーは比較した内容を返しません。
    readHunks array 確認者が既読にしたハンクのインデックス。
    confirmedHunks array 確認済みにしたハンクのインデックス（#288）。確認状態を持たないビルドでは省略し、レポートは推測せずその旨を明記します。
    comparisonState object Web UIが取得するバージョン付きURL状態（v、mode、paths、controls）。
    reproduceURL string APIトークンを含まない共有URL。そのまま記録されます。

    レスポンスはContent-Disposition: attachment付きのダウンロードで、ファイル名はayame-report.json、ayame-report.md、ayame-report.htmlです。レポートには、比較対象（サイズ、更新日時、検出エンコーディング、SHA-256ハッシュ）、比較条件、総数、無視した各ハンクと理由、既読/未読状態、比較を再実行する#compare=フラグメントが記録されます。対応するのはtextとsortedの比較です；CSV、フォルダ、3-wayのレポートは未実装です。

    CSVとファイルAPI¶

    POST /api/file/readは編集用にテキストファイル全体を返します（行、保存時に復元する 文字コード/BOM/改行の情報、サイズと更新時刻のスタンプ、書き込み可否）。8MiBを超える ファイルは拒否します。POST /api/file/saveはその情報を使って書き戻します。 overwrite: trueが必須で、リクエストにexpectスタンプがある場合は、その後に変更 されたファイルへの書き込みを拒否し、forceが無ければコードstale_writeで409を 返します。

    • GET /api/files?path=...：ローカルディレクトリのエントリを最大2,000件リストアップ（設定ファイルピッカー用）。
    • POST /api/watch：1〜3個のファイルパスと任意の前回baselineを受け取ります。 baselineなしでは現在のsnapshotを即時返し、指定時はサイズ・更新時刻・モードが変わるか 20秒経過するまで待ちます。返されたsnapshotを次のbaselineとして再送します。 1リクエストが無制限の再帰走査を意味しないよう、ディレクトリは拒否します。
    • POST /api/csv/inspect：CSV設定JSONを受け取り、データ行をスキャンせずに最初のレコードのスキーマを検査。
    • POST /api/csv/diff：完全な比較を実行し、ヘッダー、列ごとの件数・割合・数値差を含むサマリー、最大maxRowsの論理JSONセル差分（デフォルトは500、最大5,000）、および解決後のbudget_bytes、サーバーのcap、spilledフラグ、spillが起きた場合のspill_dirを伝えるmemoryオブジェクトを返す。
    • POST /api/csv/export：同じリクエストにoutput、outputFormat（tsvまたはjsonl）、outputHeaderを追加し、完全なローカル結果を書き出す。
    • POST /api/csv/suggest：候補オプション集合の有界なリスト（最大8件）を評価し、それぞれの残差差分件数のみを返すため、UIは完全な差分ビューを実行せずに提案を見積もれます。

    これらのエンドポイントは意図的にローカルパスを受け付けており、GUIの他の部分と同じくローカル・シングルユーザー利用と明示的なリモートモードの警告が適用されます。
